# Security policy

## Supported versions

Until the first stable v2 release, security fixes are made on the default development branch. After release, supported versions will be listed here.

## Reporting a vulnerability

Do not open a public issue for a suspected vulnerability. Use GitHub's **Report a vulnerability** feature in the repository Security tab to submit a private advisory to the maintainers.

Include the affected version or commit, operating system, impact, reproduction steps, and a minimal proof of concept. Remove real client names, targets, credentials, cookies, tokens, and scan artifacts. Synthetic or local fixtures are preferred.

If private vulnerability reporting is unavailable, open a public issue containing no vulnerability details and ask a maintainer to enable a private channel.

## Scope

Security reports about Aquatone Revamped itself are welcome. Findings on systems scanned with Aquatone Revamped must be reported to the owner of those systems, not to this project.
